01 · Project overview

From manual checking to intelligent inspection.

Surface defects can affect product quality, reliability and downstream manufacturing. This project explores how computer vision and sensor-based measurement can support a more repeatable inspection workflow.

01

Problem statement

Visual inspection may depend on operator attention, lighting and experience. Small or unfamiliar surface defects can be difficult to identify consistently. An image-based assistant can help flag areas for review.

02

Project aim

Develop a prototype that analyses steel surface images, measures object height with an ultrasonic sensor, and demonstrates how inspection results could support product classification.

03

Key objectives

Detect known defects, highlight unusual patterns, provide an accessible testing interface, measure object height, and design a path toward controller-based rejection and IIoT monitoring.

Scope and current statusThe deployed web application demonstrates image-based model inference. The Arduino/HC-SR04 setup is a separate height-measurement module. Do not describe automatic physical rejection or full IIoT integration as operational until end-to-end hardware communication and actuator tests have been completed.
02 · AI and software

Two models, complementary roles.

The web application processes an image submitted by the user. YOLO and PatchCore provide different types of evidence and should be interpreted separately.

Object detection

YOLO

Predicts learned defect categories and localizes detections with bounding boxes and confidence scores. Performance depends on image quality, representative training data and the similarity of test images to the training domain.

Anomaly detection

PatchCore

Learns normal visual patterns and highlights regions that look anomalous. An anomaly score is not a defect probability; its threshold must be calibrated using representative validation samples.

Target categories

Six surface defects

Crazing · Inclusion · Patches · Pitted surface · Rolled-in scale · Scratches. These are the six classes configured for the YOLO model.

Image interface

Camera and batch upload

The intended interface supports phone-camera capture in compatible browsers and batch uploads of up to six images, depending on the currently deployed app version.

Development stack

Python + Streamlit

Python-based inference and a Streamlit interface provide the demonstration workflow. OpenCV and the relevant model libraries support image processing and inference.

Future connection

IIoT integration

Potential next steps include transmitting inspection decisions to a controller, logging results, monitoring device status and connecting the inspection station to a production dashboard.

03 · Hardware modules

Measuring and moving the product.

The hardware work complements AI inspection by exploring object-height measurement and a possible conveyor-based sorting setup.

A

Arduino Uno + HC-SR04

The HC-SR04 sends an ultrasonic pulse and measures the time for its echo to return. The Arduino converts this echo time into distance. Keep the sensor steady and perpendicular to the reference surface for more consistent readings.

B

Height calculation

With the sensor mounted above the object, calculate: Object height = reference distance − measured distance. The current setup uses an approximately 15 cm sensor-to-ground reference; remeasure the real distance before testing.

C

Conveyor and rejection concept

A DC geared motor can move products through the inspection point. A motor driver and a suitable actuator would be needed for motion and rejection. These parts require electrical, timing and mechanical validation before automatic operation.

Height measurement — practical procedure

1

Measure the reference

With no object under the sensor, measure the sensor-to-platform distance and use it as the reference value.

2

Read the object distance

Place the object under the sensor and read the distance to its upper surface. Avoid angled, moving or very soft targets during initial testing.

3

Calculate and compare

Subtract the measured distance from the reference distance. Compare the result with a ruler or known object to check error and repeatability.

04 · System workflow

From input to inspection decision.

1

Height Measurement

The Arduino/HC-SR04 module estimates object height from the reference distance and measured distance.

2

Validate Height Result

Compare the measured height with predefined acceptable height limits to determine whether the product meets specifications.

3

Run Image Processing Model

Capture or upload the product image and process it using the YOLO and PatchCore models to detect surface defects.

4

Review and validate

Review the predicted defect class and anomaly results to determine whether the product surface is acceptable.

5

Making Decision

Combine the height measurement and image-processing results to classify the product as PASS or REJECT.

6

Product Rejection

If either the height or surface quality fails the acceptance criteria, reject the product using the rejection mechanism; otherwise, allow it to pass.

System architecture

Product→Height Measurement→Pass / Reject
Image Capture→Image Processing→Pass / Reject
05 · Model evaluation

Reported YOLO results.

These are the previously reported evaluation metrics for the current YOLO model. They should be presented with the evaluation dataset and test conditions whenever those details are available.

01

Precision

60.33%

Of the model's predicted defect detections, the proportion that were correct under the evaluation setup.

02

Recall

70.84%

Proportion of labelled defect instances detected under the evaluation setup.

03

mAP@50

70.73%

Mean average precision using an intersection-over-union threshold of 0.50.

04

mAP@50–95

37.61%

Mean average precision averaged across IoU thresholds from 0.50 to 0.95; this is a stricter localization metric.

05

What the metrics mean

Precision and recall describe different error types. mAP scores summarize detection performance. None of these metrics alone guarantees reliable performance on every real-world product.

06

Next validation steps

Review class-wise confusion, false positives and missed defects; test on unseen images; standardize lighting and camera distance; and document results for each defect class.

Be transparent during presentationThese are reported model metrics, not a live accuracy guarantee. Add the dataset name, number of test images, class-wise results and date of evaluation when you have verified them. Do not invent missing dataset statistics.
